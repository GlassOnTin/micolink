# micolink

Browser configuration and telemetry console for MicoAir range/optical-flow
sensors (MT-01, MT-15, MTF-01, MTF-02) speaking the Micolink protocol, plus a
protocol specification the vendor has not published: [docs/PROTOCOL.md](docs/PROTOCOL.md).

Written from the vendor tool's behaviour and the sensors' public documentation.
Not affiliated with or endorsed by MicoAir. "Micolink" and "MicoAir" are the
owner's marks, used nominatively.

## What works

- Frame codec (`web/micolink.js`) with a test suite: builders, payload
  decoders, and a stream parser tested against fixed hex vectors. Run it with
  `node test/frame_test.mjs`. No dependencies.
- Parser and codec have been cross-checked byte-for-byte against an
  independent reference implementation (the test fixtures were generated by it).
- Web console (`web/index.html`) that talks to a sensor over Web Serial:
  reads device identity from heartbeats, streams RANGE_SENSOR 0x51 /
  OPTICALFLOW 0x55 telemetry, and reads/writes the undocumented PARAM1
  configuration block (GET/SET commands).

## What is not verified

Tested against the vendor's software behaviour, not yet against live hardware
over the wire end to end. In particular: the mapping of GET_PARAM1's baudrate
byte to real baud rates is unknown, SET confirmation semantics beyond the ACK
echo are unknown, and the device heartbeat rate is unmeasured. The protocol
document carries a full list under "Known gaps and unverified areas". Firmware
read/write in MSP or MAVLink modes is out of scope (standard protocols).

## Running

Serve the directory and open it in Chrome or Edge (Web Serial needs a secure
context; `localhost` counts):

```sh
python3 -m http.server
```

Then connect a sensor through a USB-serial adapter, pick the port, and the
console sends a GET_PARAM1 on connect. Through a flight controller you can use
a USB CDC passthrough port (VID 1209:5740, generic CDC) the same way.

## Web Serial vs WebUSB

Web Serial is used, not WebUSB, and that is deliberate. These sensors appear
as CDC-ACM serial devices (or sit behind USB-TTL bridges). WebUSB cannot
usefully claim a CDC data interface: the OS serial stack owns it, and claiming
it would mean reimplementing serial line handling in the page. Web Serial's
`navigator.serial` gives the same browser-side ownership story (no driver, no
native app) over a port abstraction. The transport is in
`web/transport.js`, isolated from the codec, so a WebUSB or BluetoothSerial
transport can slot in without touching the codec.
